Detailed Description

Mediator and Subject of workflow system.

Author
Simon Vogel and Nathan Spavins

As Mediator, engine is single point that every WorkNode reports to through notify(). Tasks never talk to one other: each task only notifies, and engine decides course of action (activating follow-on tasks, detecting that workflow is finished, resolving an undo)

As Subject of the Observer pattern, engine publishes WorkflowEvent to each attached WorkflowObserver, the engine owns each WorkflowInstance it creates. It does not own its observers.

Note
WorkNode, Task and WorkflowInstance must declare friend class so the engine can read private fields

◆ activateNext()

void WorkflowEngine::activateNext ( WorkflowInstance &  i)

Mediator entry point, node reports event.

Engine finds which instance sender belongs to, publishes the event to observers unchanged, then reacts:

  • "completed"/ "rejected": activates any tasks that are ready. After "completed," also publishes "instance_completed" if whole workflow is done
  • "undone": returns downstream tasks that aren't ready anymore to Available

Events from nodes that don't belong to any instance are ignored

Parameters
senderNode reporting the event
eventStated as "completed", "rejected", "escalated" or "undone".
